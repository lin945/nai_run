# 奶龙快跑详细方案

> 2026-09-26；以 [可行性分析](./feasibility-analysis.md) 为输入。实施范围为本地可玩的 3D 单人网页游戏及可部署配置。GitHub 私有仓库和 Cloudflare 账号接入由用户准备好后再执行。

## 1. 目标与验收

玩家在第三人称视角下操控奶龙沿三条车道持续向前。左右换道、跳跃和下滑翻滚可躲避随机出现的车辆、其他角色、低路障与高横杆；收集星星加分、获得加速和吸铁石；距离持续计分；碰到不可通过的障碍立即结算。电脑和手机均可完成一局、暂停与重开。

首版成绩仅保存在浏览器。未来排行榜使用同域 Cloudflare Worker API + D1；本版只在前端集中封装成绩读写，不创建无功能的数据库和 API。

验收分为三层：

1. **规则：** 换道不越界；跳跃只能通过低路障，翻滚只能通过高横杆；车辆和其他角色无法穿过；生成的路段至少保留一条连续可达的安全路线；加速、吸铁石、星星和距离计分有效。
2. **体验：** 角色与世界真实 3D；摄像机在角色背后；跑、跳、翻滚、换道、碰撞有动作反馈；键盘和触屏操作一致；失败后可以立即再来一局。
3. **交付：** `npm run build` 成功，`npm test` 通过，桌面和手机浏览器完成实际试玩；Wrangler 配置可用于 Workers Static Assets，正式部署与域名连通性在账户授权后验证。

## 2. 技术和部署边界

| 层 | 选型 | 责任 |
| --- | --- | --- |
| 浏览器游戏 | TypeScript + Three.js，Vite 构建 | WebGL 2 场景、游戏状态和循环、碰撞、输入、声音 |
| 界面 | 原生 HTML/CSS | 开始页、HUD、暂停、结算、手机触控提示；避免在逐帧逻辑里重建 DOM |
| 本地数据 | `localStorage` | 最高分与声音偏好；统一在 `src/platform` 访问 |
| 首版云端 | Cloudflare Workers Static Assets | 分发 `dist/`，SPA 路由，绑定 `nai.bilibili.asia`；不执行游戏循环 |
| 未来后端 | 同一 Worker 的 TypeScript API + D1 | `/api/*` 读写排行榜；按需增加身份、限流和服务端成绩校验 |

Workers Static Assets 支持只发布静态文件、无需 Worker 脚本；未来可选择让 `/api/*` 先进入 Worker。D1 可通过 Worker binding 查询。[静态资源](https://developers.cloudflare.com/workers/static-assets/)、[API 路由](https://developers.cloudflare.com/workers/static-assets/binding/)、[D1](https://developers.cloudflare.com/d1/worker-api/)

首版不引入 React、物理引擎、后端路由框架和 ORM。车道跑酷只需要少量明确的几何碰撞与状态，使用这些依赖不会提升首版的可玩性。

## 3. 坐标、视角和移动

- 世界采用 Y 向上，角色固定在靠近屏幕的位置，面向 `-Z`；车道中心 X 分别为 `-3.2 / 0 / 3.2`。赛道和物体向 `+Z` 移动，玩家的“距离”单独累计。这可让无限跑保持稳定坐标。
- 透视相机位于角色后上方，平滑朝角色前方的预视点看。屏幕窄时调节视场角或相机距离，使三道和前方障碍保持可见。
- 逻辑以固定时间步更新，渲染使用 `requestAnimationFrame`；切回后台后暂停，恢复时限制大时间差，防止一次跳过碰撞。
- 车道由整数 `0..2` 表示，输入只改目标车道。视觉 X 平滑趋近目标，碰撞以当前视觉位置和宽度判定，避免换道中“瞬移穿墙”。

## 4. 状态、输入和动作

状态机：`READY → RUNNING ⇄ PAUSED`，`RUNNING → GAME_OVER → RUNNING`。`READY`/`GAME_OVER` 不推进赛道、计时器或分数。重新开始完整清理旧障碍、星星、道具及临时效果。

| 动作 | 电脑 | 手机 | 游戏规则与视觉 |
| --- | --- | --- | --- |
| 左右换道 | ←/→ 或 A/D | 左/右滑 | 一次一条道；在最外侧忽略继续外移；角色稍作侧倾 |
| 跳跃 | ↑、W、空格 | 上滑 | 地面触发；抛物线高度；起跳和落地有姿态过渡 |
| 翻滚 | ↓、S | 下滑 | 有固定时长和冷却；碰撞体降低；身体前滚/俯身 |
| 暂停/继续 | Esc/P 或按钮 | 按钮 | 停止运动、计分、道具计时和声音节奏 |

触屏只在游戏区域识别，设最短滑动距离并忽略斜向误触。UI 按钮不触发角色手势。动作优先级建议为：失败 > 翻滚 > 跳跃 > 奔跑；换道可与跳跃/翻滚叠加。重力和动作持续时间集中配置，不散落魔法数字。

角色首版采用**程序化 3D 网格**：圆润黄色躯干、浅色腹部、短臂短腿、背部小尾巴，根据 `res/` 匹配主要形态；关节和主体每帧摆动实现跑、跳、翻滚、侧倾和撞击。这样无需等待外部模型即可交付真实 3D 玩法。日后得到授权的 `.glb` 模型时，可在 `Player` 渲染层替换模型和动作，不改变游戏规则。[glTF 加载](https://threejs.org/docs/pages/GLTFLoader.html)

## 5. 路段生成与碰撞

世界由循环使用的赛道路段组成，只维护相机前方有限路段，过身后回收到远方。障碍和收集物复用网格或使用实例化渲染，避免长时间跑导致对象数量持续增加。

生成器按行生成事件，每行三道中最多两道放置致命或需要动作的障碍，并保留一个无障碍安全道。下一行的安全道最多相邻移动一格；行间距离按最高速度和两次换道时间留出反应窗口。该约束使不使用跳/滚也存在可达通路，同时玩家可选择通过跳/滚走更高奖励路线。使用可重放的随机种子，纯逻辑单测验证长序列始终满足约束。

| 对象 | 通过条件 | 碰撞与反馈 |
| --- | --- | --- |
| 汽车 | 换道 | 占据整道，接触即失败；轮子/车灯有运动反馈 |
| 其他角色 | 换道 | 移动的角色障碍；接触即失败 |
| 低路障 | 跳跃或换道 | 玩家底部达到足够高度才安全 |
| 高横杆 | 翻滚或换道 | 玩家碰撞体高度降低时安全 |
| 星星 | 接触，或磁铁有效范围内 | 消失、播放粒子与加分反馈 |
| 加速道具 | 接触 | 一段时间内速度提高；撞障碍仍失败 |
| 吸铁石 | 接触 | 一段时间内吸取附近星星 |

碰撞在逻辑坐标中判定：每个对象有车道/X、Z、尺寸与类型；沿前进方向进入角色碰撞窗口时计算水平重叠，再依据跳跃高度、翻滚状态判定。已处理对象移除或回收，不能在连续帧重复结算。移动障碍使用相对速度。规则逻辑不依赖 Three.js 网格，便于测试。

## 6. 计分、难度与道具

- `distanceMeters += speed * dt`，`score = floor(distanceMeters) + stars * 10`；总分、距离与本局星星实时显示。最高分只在结算时写本地，存储失败时游戏仍可继续。
- 初速、最高速度、随距离提升的速度曲线写在配置；加速为有结束时刻的临时倍率，结束后回到当前基础速度；道具计时在暂停时不流逝。
- 磁铁按逻辑距离收星，并有明显吸附动画；重复拾取刷新持续时间，不无限叠加倍率。
- 生成节奏随距离增加，但最大速度和最小安全行距都要受上限约束，不允许难度增长到物理不可达。
- 本地成绩的格式带版本号，便于以后迁移；未来线上榜单不直接信任浏览器提供的总分，需单独做成绩验证。

## 7. 画面、声音与兼容

画面方向采用明亮卡通城市/游乐场：暖黄角色、奶油色地面、天空蓝远景、清晰区分的三道、障碍色形对比。菜单可使用现有参考图，游戏中的主体必须是 3D。音效可先用少量 WebAudio 合成，避免再引入资源包；用户可静音。

手机以竖屏体验为优先，同时保证横屏可玩；电脑宽屏保持 HUD 与赛道的比例。适配安全区和高 DPI，动态限制像素比、阴影与粒子数量。WebGL 2 不可用时展示明确提示。目标测试环境为 Chrome/Edge 桌面、Android Chrome、iOS Safari；目标手机约 30 FPS、电脑约 60 FPS，最终以真实设备测量。[Three.js WebGL 2 要求](https://threejs.org/docs/pages/WebGLRenderer.html)、[WebGL 性能建议](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices)

## 8. 代码组织和数据流

```text
src/main.ts                 组合游戏和 UI，处理应用生命周期
src/game/config.ts          唯一的调参位置
src/game/rules.ts           纯函数：生成、计分、碰撞判定
src/game/Game.ts            场景、时钟、状态机与系统编排
src/game/Player.ts          3D 角色模型与动作表现
src/game/World.ts           路段、障碍、星星与道具网格
src/game/Input.ts           键盘/触屏转统一动作
src/ui/Hud.ts               开始、计分、暂停、结算界面
src/platform/scoreStore.ts  本地成绩存储边界
src/styles.css              响应式界面
worker/                     未来增加 API 时再创建
```

数据流：输入事件 → 统一动作 → `Game` 更新规则状态 → 碰撞/计分 → `World` 和 `Player` 渲染 → `Hud` 按变化刷新。`rules.ts` 无 DOM/Three.js 依赖；`scoreStore.ts` 不参与逐帧更新。只为已有责任建文件，不建立空抽象层。

## 9. 构建、质量与上线边界

本地命令为 `npm run dev`、`npm test`、`npm run build`。测试覆盖安全通路、车道边界、跳/滚与障碍匹配、星星/距离计分、道具计时和重开清理；浏览器试玩覆盖输入及 HUD。`wrangler.jsonc` 指向 `dist/` 并声明 SPA 路由；`nai.bilibili.asia` 可配置为 Custom Domain，实际部署需账号授权及 Zone 管理权。[SPA 配置](https://developers.cloudflare.com/workers/static-assets/routing/single-page-application/)、[Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)

GitHub 私有仓库、Cloudflare 授权与最终域名访问尚待用户准备。公开发布前核对角色形象和新增资源的使用权。`res/` 保留为参考来源，运行时只打包用到的资源。
